# A股量价异动策略 v9（可迁移版）

一套完整的 A 股超跌反弹选股 + 持仓跟踪系统。全部依赖开源数据源，无账号、无 Token，换台电脑装完依赖即可运行。

---

## 一、日常使用

### 盘中盯盘（选股）
```bat
python live_scout.py --pool=400 --workers=12
```
或双击 `scout.bat`。

产出：
- `results_live/top5_<日期>.csv` —— 当日入选个股，**最多 3 只**（主要看这个）
- `results_live/live_<日期>.html` —— 完整报告，TOP 清单在最顶部
- `results_live/signals_<日期>.csv` —— 当日全部信号（含被门槛过滤前的完整记录）

> **宁缺毋滥**：某天只有 1~2 只达标就是只有 1~2 只，不要为了凑满 3 只去买入低质量信号。
> 实测 2026-09-09 全市场 6 个信号里只有 2 只达到 1.5×，而唯一涨停的那只正是同期放量最高的（1.95×）。

### 持仓跟踪（出场判定）
```bat
python track_positions.py --init=2026-09-09 --max-positions=3
python track_positions.py
```
或双击 `track.bat`（自动取当天日期）。

状态存在 `results_live/positions.json`。

> **强烈建议：买入当天就在券商 APP 挂「+5% 止盈条件单」。**
> 脚本的止盈判定用「日 K 收盘价」，盘中冲高回落是吃不到的。
> 实例：2026-09-09 英唐智控盘中最高较买入价 +3.9%，收盘反而是 -3%。
> 挂条件单可以让券商在盘中触发时自动卖出，不依赖任何人盯盘。

### 回测验证（可选，跑一次约 40 分钟）
```bat
python monthly_validate.py --months=2024-09,2024-10 --sample=300 --workers=12
python report_mv.py
```
- `monthly_validate.py` 逐月扫历史，结果落在 `results_mv/signals_<YYYYMM>.csv`
- `report_mv.py` 汇总成 `results_mv/report.html`

> 首次跑回测要拉大量历史数据，会生成约 285MB 缓存到 `.cache_v2/`。
> 想省时间可以把原机器的 `.cache_v2/` 一起拷过来（不是必需）。

## 二、策略规则（v9）

### 选股（每天盘中触发）
| 步骤 | 规则 |
|---|---|
| 1. 候选池 | 全市场快照，按成交额取前 400，剔除 ST / 北交所 / 极端涨跌 |
| 2. 下跌筛选 | 近 5 个交易日累计下跌：**A 级 ≤ -3%**，**B 级 ≤ -1%** |
| 3. 放量脉冲 | 15 分钟 K 线：当根涨幅 **0~2%**，成交量 **≥ 前一根 × 2** |
| 4. 排除 bar | 剔除 11:30、13:15、15:00 三根（跨午休/收盘失真） |
| 5. 同期放量 | 今日截至该 bar 累计量 ÷ 昨日截至同一 bar 累计量，**≥ 1.5×**（v9 核心，原 0.9） |
| 6. 同票去重 | 同一只票当天多根 bar 触发时，只保留同期放量最强的那根 |
| 7. 排序取前 3 | 按**同期放量倍数**降序，**最多 3 只**，宁缺毋滥 |
| 8. 强度分级 | ★★★ ≥2.3×、★★ ≥1.8×、★ ≥1.5× |
| 9. 追高保护 | 现价比信号价高 **3%** 以上标「慎追」，不建议追 |
| 10. 标注 | 平静度 = 前 3 根量 最大/最小；爆发 = 信号根量 / 前 3 根均量。仅标注不过滤 |

### 出场
- 买入价 = 信号根 15min 收盘价，每只约 1 万元（按 100 股整手取整）
- **T+1 起 5 个交易日内，日 K 收盘 ≥ 买入价 × 1.05 止盈卖出**
- 第 5 个交易日收盘仍未止盈 → 强平
- **不加止损**

### 关键参数的回测依据（2024-09 ~ 2026-08，24 个月，11469 条信号）

| 结论 | 数据 |
|---|---|
| **今/昨量比门槛 0.9 → 1.5**（v9 最重要改动） | 见下方分档表，收益随量比**严格单调** |
| 排序用「同期放量」而非「瞬时量比」 | PF **1.80** vs 1.35，平均单笔 +1.33% vs +0.66% |
| 止盈 +5% 而非 +1% | PF **1.35** vs 1.13，平均单笔 +0.71% vs +0.15% |
| 不加止损 | -3% 止损 PF 1.13 → **0.87**；-5% → 0.99 |
| 大盘 MA20 择时**默认关闭** | 过滤 PF 1.32 vs 不过滤 **1.35**，且少 1/3 机会 |
| 每日 5 只 → 最多 3 只 | 减少资金占用，把钱集中在最强的信号上 |

**今/昨量比分档（已扣 0.25% 手续费印花税）——收益随量比严格单调：**

| 量比档位 | 交易数 | 胜率 | 净均单笔 | PF |
|---|---|---|---|---|
| 0.9~1.2 | 1947 | 68.1% | +0.61% | 1.33 |
| 1.2~1.6 | 1663 | 71.1% | +1.03% | 1.64 |
| 1.6~2.2 | 1066 | 72.2% | +1.40% | 1.90 |
| >2.2 | 642 | 78.2% | **+2.17%** | **2.63** |

旧门槛 0.9 正好把最差的那一档（PF 1.33、扣费后几乎白干）全部放了进来，这是原策略最大的拖累。
门槛 1.5 时：净均 +1.39%、PF 1.86，日均约 3.2 只。

> 口径提醒：回测用的是「全天口径」今/昨量比，实盘 13:30 只能算「同期口径」，
> 实测同期 ≈ 全天 × 1.56（中位数）。脚本里的 1.5 / 1.8 / 2.3 是**实盘同期口径**阈值。

### 必须知道的两个局限
1. **回测存在幸存者偏差**：候选池用 2026-08 的成交额排名回测历史月份，实盘预期要打折。
2. **成本敏感**：+0.66%/笔 扣掉手续费印花税（约 -0.15%~-0.2%）后很薄，滑点再吃一些就可能打平。
3. 回测里的「同期放量」是**全天口径**，盘中 13:30 只能算**同期口径**，两者相关但不是一回事——v8 实际优势大概率低于 1.80。

## 五、常见问题

**Q：跑到一半报 501 / 数据为空？**
腾讯接口限流。脚本已切到 `ifzq.gtimg.cn`，若仍遇到，等几分钟重试即可。

**Q：程序卡住不动，几十分钟没输出？**
已修复，不会再发生。原因有两个，均已处理：
1. `baostock` 的 socket 没有超时保护，服务端挂起时会永久阻塞 —— 现在关键探测都加了线程超时；
2. **更隐蔽的一个**：`while rs.next():` 游标迭代在 baostock 0.9.30 + pandas 3.0 下会**死循环**
   （实测无论指数还是个股都必现），代码已全部改为 `rs.get_data()` 一次性取回。
   如果你从别处拷来的旧版本遇到卡死，搜一下 `rs.next()` 就是它。

**Q：回测第一次跑很慢？**
正常。首次要构建股票池：用 baostock 逐只拉 5000+ 只股票的日均成交额，约 15 分钟，
之后缓存在 `.cache_v2/`，再跑就快了（单月约 20 秒）。

**Q：某天一只信号都没有？**
正常。策略只做「近 5 日下跌 + 盘中放量」的票，大盘单边上涨或极度缩量时可能空仓。

**Q：能改参数吗？**
在 `live_scout.py` 顶部常量区：
- `SAME_VOL_MIN`（同期放量硬门槛，当前 1.5，**最敏感的一个**）
- `SAME_VOL_MID` / `SAME_VOL_STRONG`（强度分级阈值，1.8 / 2.3）
- `TOP_N`（每日最多几只，当前 3）
- `CHASE_LIMIT_PCT`（追高上限，当前 3.0%）
- `DECLINE_A` / `DECLINE_B`、`MIN_TURNOVER`、`MA20_FILTER`

出场参数在 `track_positions.py` 的 `TP_PCT`（当前 1.05）。

**Q：信号出来就涨停/直线拉升，买不进怎么办？**
这是正常且**不该追**的。脚本会计算「现价 vs 信号价」偏离，超过 +3% 标红「慎追」。
2026-09-09 湖南黄金 13:30 出信号 26.75，14:09 已涨停 28.45（+6.4%）——这种就放弃，等下一只。
不要因为某只涨得好就后悔没买，长期看追高的期望收益是负的。

**Q：持仓数据怎么迁？**
把 `results_live/positions.json` 一起拷过来即可，已包含在本包中。

## 六、云端部署（GitHub Actions + PushPlus 微信推送）

不想一直开着本机？把策略丢到 GitHub 私有库，由 GitHub Actions 定时跑、结果推到你微信。**零成本、不租服务器**（GitHub 私有库 2000 分钟/月免费，PushPlus 免费 200 条/天，都够用）。

### 整体架构
```
GitHub 私有库 (ashare_v8 全部文件 + .github/)
   └─ scout.yml  每周一~五 交易时段 北京时间 每半小时(9:00~15:30, =UTC 01:00~07:30) 跑 live_scout.py
         → 生成信号 → **有信号才推** PushPlus 完整 HTML 报告到微信(无信号静默, 不刷屏)
         → 跑完把 results_live/ 提交回仓库, 持久化信号去重 state.json
```

### 部署步骤（一次性）
1. **建私有仓库**：GitHub 上 New repository（私有，名字随意，如 `ashare-signal`）。
2. **推代码**：把本 `ashare_v8` 目录全部内容（含 `.github/` 文件夹）推到仓库。
   ```bash
   cd ashare_v8
   git init && git add -A && git commit -m "init"
   git remote add origin https://github.com/<你>/<仓库>.git
   git push -u origin main
   ```
   > 已内置 `.gitignore`：`.cache_v2/`、`results_mv/`、`__pycache__/` 不会被推上去（云端不跑回测，只留 `results_live/` 持久化）。
3. **配推送 token**：仓库 → **Settings → Secrets and variables → Actions → New repository secret**
   - Name：`PUSHPLUS_TOKEN`
   - Secret：去 [pushplus.plus](https://www.pushplus.plus) 注册后复制你的 token 填进去
   - ⚠️ **token 只存 secret，不要写进任何代码/README**（本仓库代码里也读的是环境变量）。
4. **完成**。scout 会自动按北京时间**每半小时(9:00~15:30)**触发，抓到信号才推送到你微信（无信号静默）。

### 推送内容
| 时间(北京) | 推送 | 内容 |
|---|---|---|
| 每半小时(9:00~15:30) | `盘中信号 <日期> · 新增 N 只`（**仅当有信号时**） | 完整 HTML 报告（TOP 清单在最顶部，可直接在微信里看） |

> **静默推送**：scout 每半小时跑一次，但**只有抓到信号才推微信**；无信号的那次静默跳过，
> 不会每半小时给你刷一条「无信号」把微信刷屏。持仓跟踪（`track_positions.py`）不再由云端自动跑，
> 如需查看模拟盈亏可在本机手动执行（见「一、日常使用 → 持仓跟踪」）。

### 几个关键设计点（已为你处理好）
- **时区**：GitHub runner 系统时钟是 UTC，脚本已统一改用 `Asia/Shanghai`。scout 的 cron `*/30 1-7 * * 1-5` = 北京 **9:00~15:30 每半小时**，你**不用**管时区换算。
- **不自动建仓 / 不跟踪持仓**：云端只做「扫描 + 有信号推送」，不再自动建模拟持仓、不再每日推送持仓跟踪（这两步原由已删除的 `track.yml` 负责）。`track_positions.py` 仍保留在仓库，可在本机手动跑（见「一、日常使用 → 持仓跟踪」）。
- **持久化**：`state.json`（信号去重）每天自动提交回仓库，跨天连续。
- **轻依赖**：云端 `requirements.txt` 只装 `pandas/numpy/requests`，**不装 baostock/akshare/tqdm**（都做了软降级）。回测才需要 baostock，云端不跑回测。
- **手动触发**：仓库 → Actions → 选 workflow → `Run workflow`，可随时手动测一次。

### 已知限制
- **节假日**：GitHub cron 不认 A 股节假日，节假日当天会照常跑，但无信号/数据异常，推送忽略即可。
- **cron 抖动**：GitHub 定时任务可能延迟 5~15 分钟，对每半小时扫描影响很小。
- **时效性（重要）**：信号基于「已收盘的 15 分钟 K 线」，从信号产生到你看到微信推送，中间隔着扫描间隔 + GitHub 抖动（5~15 分钟）+ 你读消息的时间，活跃小票（创业板/科创板）在这 20~40 分钟里完全可能已涨 3~4%。本系统定位是**「选股 / 复盘」工具，不是实时成交信号**：推送时股价通常还在信号价附近（报告里的「追高%」即现价 vs 信号价），若你看到时已被拉高，说明你接收得晚了，而非信号本身过时。真要据此下单，建议在扫描时点附近盯盘，或提前挂条件单。
- **推送是模拟**：微信里看到的是「若按信号买入」的纸上结果，真实交易仍以你券商账户为准（强烈建议挂 +5% 条件单）。
